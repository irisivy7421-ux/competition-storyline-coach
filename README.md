# Competition Storyline Coach

一套面向路演、案例赛、创新赛与答辩场景的 Codex Skill：读取比赛命题和评分规则，通过有进度提示的启发式访谈，帮助选手形成可验证的创新方案、比赛故事线、评分覆盖分析和飞书文档。

它不会从一张通用模板直接生成“看起来完整”的方案。它先检查命题和评分规则是否完整，再用有限问题寻找真实用户、关键场景、方案机制、AI 的核心作用与验证路径。

## 适用场景

- 企业命题赛、商业案例赛和 AI 创新赛
- 产品路演、项目答辩和创业比赛
- 需要按照明确评分标准组织内容的比赛演讲
- 已有初步想法，希望通过提问梳理成完整故事线

普通演讲润色、没有命题与评分规则的自由创作，不是这个 Skill 的主要用途。

## 使用前需要准备什么

必须同时提供：

1. **比赛命题或企业问题**：出题背景、目标对象、需要解决的问题和期望成果。
2. **本届评分规则**：评分维度、权重、评分标准，以及已知的赛制和时间限制。

如果权重总和异常、维度重复或规则缺失，Skill 会先指出问题，不会擅自归一化或补写规则。

## 访谈体验

标准模式通常包含 5–7 个主问题，预计用时 10–15 分钟。每轮只问一个主要问题，并显示阶段、题号、进度和预计剩余时间：

```text
问题定位 ✓ → 现有缺口 ✓ → 方案机制 ● → 验证落地 ○
███████░░░ 70%｜第 5/7 问｜预计还需 3–5 分钟
```

四个访谈阶段分别是：

1. **问题与用户**：锁定具体人群、触发场景、真实阻碍及其代价。
2. **现有做法与缺口**：理解目前如何解决、为什么仍然不足。
3. **方案机制**：形成产品核心体验、AI 的关键作用和持续价值闭环。
4. **证据与落地**：确定效果指标、最小试点、风险和待验证假设。

用户可以随时回复“先总结”，Skill 会基于已有信息生成阶段性成果，并标出缺口。

## 最终会得到什么

### 1. 聊天内方案摘要

摘要可以独立阅读，包含：

- 产品概念与一句话定义
- 目标用户与关键问题
- 核心体验和 AI 工作机制
- 用户价值与企业价值
- 最小试点、验证指标和主要风险
- 完整飞书文档链接

### 2. 飞书文档完整版

在飞书文档能力、认证和权限可用时，Skill 会新建一份完整文档，包括：

- 比赛命题与评分规则
- 用户问题与现有方案缺口
- 产品方案、AI 机制和成长路径
- 企业价值与推广逻辑
- 最小试点和验证指标
- 风险、假设与待验证项
- 5–7 节点比赛故事线
- 评分覆盖矩阵
- 演讲时间分配
- 访谈洞察记录

若飞书能力不可用，Skill 会先在对话中交付完整内容，并明确说明阻断原因，不会伪造文档链接。

## 事实与证据边界

输出使用三种状态：

- **已确认**：来自正式规则、用户材料或可核验来源。
- **方案判断**：根据访谈和推理形成的设计结论。
- **待验证**：缺少真实用户、数据、来源或主办方确认。

Skill 不会把产品设想写成已验证效果，也不会编造用户访谈、业务收益、推广数据或原创性证据。

## 项目结构

```text
competition-storyline-coach/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── example-rubric.md
    └── interaction-and-delivery.md
```

- `SKILL.md`：入口、访谈逻辑、证据纪律和交付要求。
- `agents/openai.yaml`：Codex 中展示的名称、简介和默认调用提示。
- `references/example-rubric.md`：含权重异常的示例评分表，用于测试规则校验能力，不是默认比赛标准。
- `references/interaction-and-delivery.md`：进度卡、提问卡、聊天摘要和飞书文档模板。

## 飞书与数据安全

- 创建飞书文档依赖调用者当前环境中的飞书工具、用户认证和文档权限。
- Skill 本身不包含飞书凭证、GitHub 令牌、内部链接或真实学生数据。
- 默认新建飞书文档，不覆盖已有文档；只有用户明确提供目标文档并要求更新时才修改。
- 比赛材料可能包含企业内部信息。上传公开仓库、公开文档或外部服务前，请确认材料的公开边界。

## 常见问题

### 为什么没有直接给我一份完整方案？

比赛方案需要同时回应命题、评分标准和真实问题。有限访谈用于确认决定方案方向的关键信息，减少“结构完整但问题错误”的方案。

### 进度百分比代表得分吗？

不代表。百分比只表示关键问题的梳理进度。比赛得分仍取决于证据质量、实际方案、现场表达和评委判断。

### 可以直接让它写演讲稿吗？

可以在确认方案和故事线后继续要求写稿。默认流程先完成方案构思与故事线，避免在事实和结构尚未稳定时过早润色文案。

### 能否用于没有明确评分规则的演讲？

不建议。普通演讲构思或润色应使用更通用的演讲写作流程。
